## CONTRIBUTING GUIDELINES

1. Fork the repo and create a new feature branch from `main`.
2. Create a draft pull request as soon possible so that it can be tracked. Draft pull requests can be created by pushing a small commit.
3. Commit all the changes to your forked repository, while adding the `-s` flag at each commit to sign the commits and then add proper messages at each of them.
4. Run all the checks retaining to the techstack that will be used before pushing.
5. Add or update tests for any behaviour change. (if any)
6. Open a PR referencing the relevant issue. Try to follow proper wording convention for the pull requests.
___
If you're looking for a starting point, check the [good first issue](https://github.com/slash-aech/grievance-portal-nita/issues?q=is%3Aissue+is%3Aopen+label%3A%22good+first+issue%22) label.

If you are new to any types of contributions in github space please follow [this](https://www.geeksforgeeks.org/git/how-to-create-a-pull-request-in-github/) to understand how general contributions work.
